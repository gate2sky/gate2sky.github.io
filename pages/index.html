How it works

One SSH command. A public URL.

Your service stays on your machine. Visitors reach it through the gate, every byte encrypted on the way.

requestsresponses🔒 SSH encryption end to end

What you get

Your gate, your rules.

Keys per subdomain

Only the SSH keys you add to a subdomain can open it.

Passkeys & email codes

No passwords. A code by email, then your fingerprint.

Public, team or private

Choose who can open each subdomain. Your app never sees the login.

Live dashboard

Who is connected, from where, requests and traffic. One click to cut it.

HTTPS by itself

Let's Encrypt certificates for each subdomain, on demand.

A wizard in the terminal

securegate config: set up, add keys and users without the browser.

Install

Pick your launchpad.

Point gate.example.com and *.gate.example.com at the server, then:

$ curl -fsSL https://jgermade.github.io/securegate/setup.sh | sh

Linux and macOS. It installs the binary, opens the setup wizard and, with systemd, runs securegate as a service. Run it again to update, reconfigure or uninstall.

… | shinstall, or update
… | sh -s -- reinstallsame version, again
… | sh -s -- configurethe setup wizard
… | sh -s -- uninstall --purgeremove it all
# configuration and state live in the volume
$ docker volume create securegate
$ docker run -it --rm -v securegate:/data ghcr.io/jgermade/securegate config
$ docker run -d --name securegate --restart unless-stopped -v securegate:/data \
    -p 80:80 -p 443:443 -p 2222:2222 ghcr.io/jgermade/securegate

Choose Let's Encrypt in the wizard: securegate gets a certificate for each subdomain on its own. Manage it later with docker exec -it securegate securegate config.

$ git clone https://github.com/jgermade/securegate && cd securegate
$ helm install securegate deploy/helm/securegate \
    --set domain=gate.example.com \
    --set traefik.tls.certResolver=letsencrypt-dns

An IngressRoute for the dashboard and every subdomain, SSH over a Traefik TCP entry point with the PROXY protocol. See the chart.
