How it works

One SSH command. A public URL.

Your service stays on your machine. Visitors reach it through the gate, every byte encrypted on the way.

requestsresponses🔒 SSH encryption end to end
From your terminal

Dial the gate.

The subdomain goes in front of the port. Every request is logged as it passes.

~ $ ssh -i ~/.ssh/gate2sky -p 2222 -R myapp:80:localhost:3000 gate.example.comgate2sky: connected with key SHA256:9fQx…kLm2✔ https://myapp.gate.example.com is now forwarding  access: private — manage it at https://gate.example.com12:04:31  200  GET    /             (4ms)12:04:31  200  GET    /app.js       (2ms)12:04:33  101  GET    /live         (websocket)

ssh offers the keys in ~/.ssh (id_ed25519, id_ecdsa, id_rsa…) and those in your agent: nothing to add when one of them is on the subdomain.

For a key kept elsewhere, such as one made just for gate2sky with ssh-keygen -t ed25519 -f ~/.ssh/gate2sky. With many keys in your agent, add -o IdentitiesOnly=yes.

What you get

Your gate, your rules.

Keys per subdomain

Only the SSH keys you add to a subdomain can open it.

Passkeys & email codes

No passwords. A code by email, then your fingerprint.

Public, team or private

Choose who can open each subdomain. Your app never sees the login.

Live dashboard

Who is connected, from where, requests and traffic. One click to cut it.

HTTPS by itself

Let's Encrypt certificates for each subdomain, on demand.

A wizard in the terminal

gate2sky config: set up, add keys and users without the browser.

Install

Pick your launchpad.

Point gate.example.com and *.gate.example.com at the server, then:

$ curl -fsSL https://gate2sky.github.io/setup.sh | sh

Linux and macOS. It installs the binary, opens the setup wizard and, with systemd, runs gate2sky as a service. Run it again to update, reconfigure or uninstall.

$ wget -qO- https://gate2sky.github.io/setup.sh | sh

For machines without curl, such as a minimal Debian: the installer then downloads with wget too. The rest is the same: it installs the binary, opens the setup wizard and, with systemd, runs gate2sky as a service.

# configuration and state live in the volume
$ docker volume create gate2sky
$ docker run -it --rm -v gate2sky:/data ghcr.io/gate2sky/gate2sky config
$ docker run -d --name gate2sky --restart unless-stopped -v gate2sky:/data \
    -p 80:80 -p 443:443 -p 2222:2222 ghcr.io/gate2sky/gate2sky

Choose Let's Encrypt in the wizard: gate2sky gets a certificate for each subdomain on its own. Manage it later with docker exec -it gate2sky gate2sky config.

$ helm install gate2sky oci://ghcr.io/gate2sky/charts/gate2sky \
    --set domain=gate.example.com \
    --set traefik.tls.certResolver=letsencrypt-dns
Traefik’s own chart, so it opens the SSH port: values.yaml 
ports:
  ssh:
    port: 2222
    expose: {default: true}
    exposedPort: 2222
    protocol: TCP

An IngressRoute for the dashboard and every subdomain, and SSH over that Traefik entry point with the PROXY protocol. Keep exposedPort and the chart’s ssh.publicPort the same; port 22 only works on an address no other sshd uses. See the chart, also in a classic repository: helm repo add gate2sky https://gate2sky.github.io/charts.
