# A design system for the dashboard

Asked: *"en el panel: las modales no se cierran al hacer click en el overlay;
vendría bien un sistema de diseño como he hecho en
https://github.com/jgermade/luu/tree/main/web/theme/default; las pestañas del
/subdomains/<subdomain_id> mejor en .page-head, como se ha hecho en /admin"*.

## The theme is a folder

`internal/web/ui/theme/default/`, after luu's `web/theme/default/`:

```
tokens.css          every value the components draw with
icons.js            the icons, one path each
components/*.html   the components
demo.html, demo.css the demo, served at /ui/theme/default/
```

### Tokens

All `--ig-*`, written once in `tokens.css`, and read by the components with
no fallback. The values are the dashboard's own (its macOS look: a drifting
wallpaper behind blurred materials), so nothing changed colour by moving.

**Two tones, by what a thing sits on**: `dark` on `:root` — light text on
the wallpaper and the toolbar — and `light`, dark text on a card, a dialog,
the toast. Any element is an island of the other with `data-tone`; `Card`
and `Modal` are light islands of their own. This replaces the old
`.card, .toast { --fg: …; }` override.

Colour by role (`fg`, `fg-muted`, `link`, `ok`, `warn`, `bad`, `fill`,
`field`, `line`, `separator`, the secondary button's glass, `tint`), what is
the same in both (wallpaper, materials, accent, danger, system colours,
hues for tiles, tile and avatar gradients, switch, roles, code), type
(`--ig-text-2xs` … `4xl`, weights), space (`--ig-space-1` … `10`), radii,
control heights (taller on a phone), shadows, motion (durations `0ms` under
`prefers-reduced-motion`, once), z-layers.

One rule beyond tokens: `[data-flow]` trims the outer margins of what is
put in a component's free-content slot (a card's body, a dialog's), since a
scoped style cannot reach slotted elements.

### Components

Each imports nothing but the theme (`Icon`, `icons.js`), takes everything as
props and slots, gives everything back through `:model`/`$emit`, and scopes
its styles:

| Component | What it is |
| --- | --- |
| `Icon` | A stroke icon by name, sized and weighted; a component takes an icon as a prop and draws it itself |
| `Button` | Tinted glass: `primary`, `secondary`, `danger`, `dark`, `plain`, `ghost`, `ghost-danger`; `sm`, `block`, `square`, `icon`, `href`, `form`; re-emits `click` |
| `Modal` | The `<dialog>`: Escape, the close button and a click on the backdrop ask to close (`close`), the owner closes it; `sm`/`md`/`lg`; a `foot` slot |
| `Tabs` | Pills with a count, an `extra` note (what is online) and a `bad` tone; arrows, Home, End |
| `Card` | A light material with an optional head (`title`, `aside` slot); `accent` and `bad` tones; `width` for one thing alone on a page |
| `Badge` | A state or a count: tones, `dot`, `pulse`, `solid`, `lg` |
| `Alert` | A message in a tone; `bad` is announced as an alert; `flush` for grids |
| `Facts` | Facts in tiles tinted by their icon's hue |
| `Switch` | Green on, red off; `:model`, or `:on` for a value the owner saves itself |
| `Segmented` | One of a few, side by side |
| `ChoiceCards` | Radio cards with an icon, a hint and a check; `row` or `stack` |

**No inline styles**: the dashboard's CSP is `style-src 'self'`, which blocks
a `style` attribute — and jq79's `:style` sets one — so sizes and widths are
classes, and the demo paints its swatches through the style object. Scoped
styles go in through `adoptedStyleSheets`, which the CSP does not govern.

### The demo

`/ui/theme/default/`, a page of its own (`templates/theme.html`, served by
`handleTheme` with a fresh nonce under the dashboard's CSP; without its
slash it redirects). It loads `tokens.css` and nothing of the app's: the
colours of both tones read back from the computed style, type, space,
radii, shadows, control heights, motion, every icon, and each component in
its variants on the wallpaper and on a card, with how it is used. The
modals can be opened and dismissed there. Covered by `TestPageSecurity`.

## The dashboard draws with it

- `app.css` declares no colour of its own (every value a token) and keeps
  only the page: wallpaper, toolbar, page heads, tables, fields, the toast,
  the copyable command. What moved into components left it: `.button*`,
  `.card*`, `.flash*`, `.badge*`, `.dialog*`, `.switch`, `.segmented`,
  `.radio*`, `.stats`, `.panel-tabs`, `.count`, `.icon-button`.
- Every view and component uses the theme's components; inline SVGs became
  `Icon`s, except the role icons inside `<option>`s, which keep only text
  and inline SVG.
- `AccessOptions` is `ChoiceCards`; `StatusBadge` and the new `AccessBadge`
  are `Badge`s.

### Modals close on the overlay

Every dialog is a `Modal`: delete a user, sign out, register a subdomain,
add and edit a port. A click whose target is the `<dialog>` itself landed
on the backdrop — its box fills the dialog, so anything inside has a target
of its own — and asks it to close, **only when the press started there
too**, so selecting text in a field and letting go outside does not lose
the form. The old dialogs had padding on the `<dialog>`, and no handler.

### The subdomain's tabs are in its head

As on /admin: the hostname and its status on the left, `Tabs` on the
right, wrapping under the title on a phone.

## Checked

In Chromium against a local server: every page and dialog at 1200 and
390 px against screenshots from before; the backdrop, Escape, the close
button, a drag that ends outside, and a dialog that refuses to be
dismissed; register, change access, tabs by click and keyboard, add and
rename keys, add a port from the dialog's foot (`form=`), edit it, copy its
address, disable and enable a user, cancel and confirm a delete, delete a
subdomain, sign out; the setup and a 404. No console errors or CSP
violations. `go test ./...` passes.

## Appended 2026-10-29: an inspector for each component

*"En el sistema de diseño, añade un botón de inspección para cada componente,
ese botón abrirá una modal con dos pestañas: una mostrará un snippet de
ejemplo de cómo se integra ese componente en un componente padre; la otra
mostrará un snippet con el código del propio componente, editable, y tendrá
preview, de modo que yo pueda hacer ajustes y poder pasarte los cambios."*

Each component's section in the demo has **Inspect** beside its title. It
opens `demo/inspector.html`, a `Modal` of the new `xl` size (1180px), with
`Tabs`:

- **Usage**: the file of a parent component that uses it — imports it in
  its `:setup`, writes it as a tag, binds it to its own state — coloured,
  with a button to copy it. One per component in `demo/usage.js`, each a
  whole component that runs on its own. They replace the short snippets the
  sections had under them.
- **Source**: the component's file, as served, in `demo/code-editor.html` —
  a textarea with transparent text over a highlighted copy of it in the
  same box and font, scrolled together (`demo/highlight.js`: markup, jq79's
  directives, the script and the style). Beside it, the preview: the Usage
  parent drawn with the code as edited. jq79 builds both from their text
  (`new C79(source, { filename, modules })`), and `modules` hands the parent
  the edited component in place of the one it imports, so nothing else on
  the page changes. It rebuilds 250 ms after the last keystroke; a parse
  error, a script that throws and jq79's warnings while it draws are listed
  under it.

A draft stays in the browser (`localStorage`, `intergate.theme-draft.<name>`)
until **Reset**, and the Source tab says *edited* meanwhile. **Copy code**
copies the file; **Copy patch** copies the change as a unified diff against
the code the draft started from (`demo/diff.js`, by longest common
subsequence, three lines of context), naming the file from the
repository's root so `git apply` takes it as is. If the file changed since
the draft started, the tab says so and Reset starts again from the new one.

Two things jq79 needed watching for. Its events bubble, so the preview's
own dialogs — the Modal's example — would close the inspector when they
close: their `close` stops at the preview's frame. And an effect that reads
and writes a component's variable wakes itself: the preview's bookkeeping
(the mounted parent, the debounce timer) lives in a closure, and problems
are noted after the moment they happen.

Checked in Chromium: every component's usage and preview, with no problems
listed; an edit that reaches the preview and not the page; a patch copied
from the page that `git apply` applies; a draft that survives a reload; a
syntax error listed under the preview; Reset; the Modal example's dialog
closed by its button, Escape and its backdrop with the inspector still
open; Tab indenting; the textarea and its coloured copy at the same box,
font and padding; a phone's width.

## Appended 2026-10-29: on GitHub Pages

*"¿El sistema de diseño es accesible desde GitHub Pages?"* — it was not: the
demo was a page of the dashboard only. *"Sí, añádelo a pages."*

Each release now publishes it at
[jgermade.github.io/intergate/theme/](https://jgermade.github.io/intergate/theme/),
beside the landing, which links to it from its footer (*design system*).

- **One page, two places.** `scripts/theme-site.sh OUT` copies the theme's
  folder and jq79 (with its notice, under `vendor/`) into `OUT`, and writes
  its `index.html` from `templates/theme.html` — the dashboard's own page
  for the demo — with the paths the dashboard serves it at made relative,
  so it works under Pages' `/intergate/` prefix or any other. Pages sends no
  CSP, so the nonce is a fixed word there; jq79 builds its scripts the same
  way and nothing checks them.
- **Nothing in the demo names a dashboard path any more.** The inspector
  imports jq79 by the name the page's import map gives it (`jq79`, the same
  module that drew the page, which its previews need), and finds the
  theme's folder from where its own modules are served
  (`demo/paths.js`: the folder above `demo/`).
- **Workflows.** The release's pages job runs the script into `site/theme`
  before it deploys. Build runs it on every push and checks what it wrote,
  and shellcheck covers it.

Checked: the site the script builds, served under `/intergate/` the way
Pages does, passes the same browser checks as the dashboard's demo — every
component's usage and preview, editing, drafts, a patch `git apply` takes,
errors under the preview, the Modal example's dialogs, a phone's width; and
the dashboard's demo still does. It goes live with the next release, like
the landing.

## Appended 2026-10-29: how the theme is loaded, a section of its own

*"Lo pondría como una sección más, y highlighted"* — the snippet that loads
the theme sat under the demo's lead, uncoloured.

It is now **Setup**, the first section under Foundations and in the index,
and both the page's snippets (Setup's and the one under Colours) are drawn
with `demo/highlight.js`, as the inspector's code is. Both are written as
markup so it colours all of them: the import sits in a `<script :setup>`,
and the recolouring in a `<style>`.

## Appended 2026-10-29: the tokens, editable in the inspector

*"En el inspector de source, me haría falta poder editar también las
variables, especialmente los colores."*

The Source tab switches between the component's file and **tokens.css**.
That view lists the tokens the component reads (`var(--ig-…)` in its
draft), or all of them, colours first: a row per token, with its value in
each tone side by side (dark, on the wallpaper; light, on a card), or one
across both for a token the tones share. A colour's swatch, drawn on its
tone's ground, opens the browser's picker; a hex stays a hex and an
`rgb()` keeps its alpha. Any value can be typed, and takes effect once
entered; one that could break out of its declaration goes back.

- **The preview alone.** The edits are declared over the theme's on the
  preview and on every island of a tone inside it, from a stylesheet the
  inspector adopts (as jq79 adopts its own: the CSP allows no inline
  style). The page keeps the theme's.
- **One draft for every component**, in `localStorage`
  (`intergate.theme-draft.tokens.css`) until Reset, as tokens.css's file is
  one. **Copy patch** carries it with the component's own change: one patch
  of both files, each value written back where tokens.css declares it
  (`demo/tokens.js` knows where each value is). If tokens.css changes
  meanwhile, the view says so, as for a component.

Checked in Chromium: a colour picked and one typed reach the preview and
not the page, a bad value goes back, the edits survive a reload and show in
another component's inspector, and `git apply --check` takes the patch.

## Appended 2026-10-29: a dark wallpaper

*"El fondo del background tiene como una capa blanquecina, sería mejor
oscura."* — the wallpaper's base, `--ig-bg`, was a mid gray (`#4b5060`)
that washed the glows over it out. *"Me gusta cómo queda el fondo al
desactivar la variable `--bg`"*: without it, the browser's own dark canvas
shows, so the base is that canvas now, near black (`#121212`, Chrome's).
The glows stay over it, as the dashboard draws them, and the dark tone's
text reads on it as before. The tunnel error page, which copies the
wallpaper, has the same base.

## Appended 2026-10-29: a pressed state for every control

*"A muchos componentes les falta un estilo para `:active`."* Only Button
had one, and its ghosts' was the same fill as their hover. Now, held down:

- **Segmented**: another option takes the fill; the chosen one is pushed
  in (`scale(.96)`).
- **Tabs**: the fill, a step past hover, and pushed in (`scale(.97)`).
- **Switch**: the knob stretches toward where it would go, its far edge
  where it was, as on macOS.
- **ChoiceCards**: the card loses its lift and settles (`scale(.985)`);
  a disabled one stays.
- **Modal**'s close button and Button's **ghost** variants give a little
  (`scale(.9)`, `scale(.92)`).
- The dashboard's own: the toolbar's tabs and the account pill take the
  fill, and **Copy** is pushed in.

Each is a transform or a colour the control already transitions, over
`--ig-duration-fast`, so reduced motion makes it instant.
